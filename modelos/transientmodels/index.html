    TransientModels (Wizards)

    En esta sección veremos el concepto de TransientModel (wizards) en Odoo: uso, ciclo de vida, vistas, acciones, contexto, patrones de varios pasos, seguridad y ejemplos prácticos.

    Concepto base: odoo.models.TransientModel

    1) ¿Qué es un TransientModel?

    Un TransientModel es un modelo temporal cuyo objetivo es recoger datos del usuario y ejecutar acciones (crear, modificar, exportar, enviar emails, etc.). Los registros se autolimpian (cron interno de Odoo) y no están pensados como tablas de negocio.

    Casos típicos: - Asistentes de creación masiva, importación/exportación. - Procesos guiados en uno o varios pasos. - Filtros previos a informes o acciones en lote. - Configuradores de opciones temporales (si necesitas configuración persistente por compañía, valora res.config.settings).

    2) Diferencias clave con models.Model

    Aspecto models.Model models.TransientModel
    Persistencia Permanente Temporal (auto-limpieza)
    Propósito Datos de negocio Formularios de acción (wizards)
    Rendimiento Depende del volumen Suele ser ligero
    Limpieza Manual Automática mediante cron
    Uso en vistas Igual que un Model Igual, pero normalmente target="new" (modal)
    Seguridad Reglas y ACL estándar Idem; pero a menudo accesible vía botones/acciones

    Nota: Los campos compute en wizards pueden usarse, pero como norma general no necesitas store=True (no tiene sentido persistir).

    3) Ciclo de vida y limpieza

    • Los registros de TransientModel se eliminan automáticamente pasado un tiempo (semana/mes según versión/configuración).
    • No confíes en ellos para guardar estado a largo plazo.
    • Si necesitas mantener una sesión entre pasos, usa un campo state o apóyate en el contexto.

    4) Estructura típica de un wizard

    4.1 Modelo (Python)

    # models/wizard_bulk_create.py
from odoo import models, fields, api
from odoo.exceptions import UserError, ValidationError

class OfficeMaterialBulkCreateWizard(models.TransientModel):
    _name = 'iscapop.create_wizard_item'
    _description = 'Item Bulk Create Wizard'

    # Datos que aporta el usuario
    category_id = fields.Many2one("iscapop.category_model", string="Category", required=True)
    location_id = fields.Many2one("iscapop.location_model", string="Location", required=True)
    quantity = fields.Integer(string="Quantity", required=True, default=1)
    condition = fields.Selection([
        ('new', 'New'),
        ('good', 'Good'),
        ('bad', 'Bad')
    ], string='Condition', required=True, default='new')

    # Soporte multi-paso (opcional)
    state = fields.Selection([('step1', 'Select'), ('confirm', 'Confirm')], default='step1')

    @api.constrains('quantity')
    def _check_quantity(self):
        for w in self:
            if w.quantity <= 0:
                raise ValidationError("Quantity must be a positive integer.")

    def action_next(self):
        self.ensure_one()
        self.state = 'confirm'
        return self._reopen_self()

    def action_back(self):
        self.ensure_one()
        self.state = 'step1'
        return self._reopen_self()

    def action_create_items(self):
        self.ensure_one()
        Item = self.env['iscapop.item_model'].sudo()
        values = {
            'name': self.category_id.name,
            'description': self.category_id.description,
            'category': self.category_id.id,
            'location_id': self.location_id.id,
            'condition': self.condition,
        }
        for _ in range(self.quantity):
            Item.create(values)
        return {'type': 'ir.actions.act_window_close'}  # cierra el modal

    # Reabrir el propio wizard para refrescar la vista/estado (patrón común)
    def _reopen_self(self):
        return {
            'type': 'ir.actions.act_window',
            'res_model': self._name,
            'view_mode': 'form',
            'res_id': self.id,
            'target': 'new',
        }

    4.2 Vista (XML)

    <!-- views/wizard_bulk_create.xml -->
    <record id="iscapop.view_item_create_wizard_form" model="ir.ui.view">
        <field name="name">Item Wizard</field>
        <field name="model">iscapop.create_wizard_item</field>
        <field name="arch" type="xml">
            <form string="Create Items">
                <group>
                    <field name="category" domain="[('create_uid','=',uid)]"/>
                    <field name="location_id" domain="[('create_uid','=',uid)]"/>
                    <field name="quantity"/>
                    <field name="condition"/>
                </group>
                <footer>
                    <button string="Create" type="object" name="action_create_items" class="btn-primary"/>
                    <button string="Cancel" class="btn-secondary" special="cancel"/>
                </footer>
            </form>
        </field>
    </record>

    4.3 Acción (XML)

    <!-- actions to open the wizard -->
<record id="action_open_create_wizard" model="ir.actions.act_window">
  <field name="name">Bulk Create Items</field>
  <field name="type">ir.actions.act_window</field>
  <field name="res_model">iscapop.create_wizard_item</field>
  <field name="view_mode">form</field>
  <field name="target">new</field> <!-- se abre como modal -->
  <field name="context">{'default_quantity': 1}</field>
</record>

    (Normalmente esta acción se invoca desde un botón en otra vista o un menú específico.)

    5) Contexto y valores por defecto

    • Puedes precargar valores mediante context (default_<field>).
    • También puedes usar default_get y @api.onchange para rellenar campos dependiendo de active_model, active_id o active_ids.
    @api.model
def default_get(self, fields_list):
    vals = super().default_get(fields_list)
    active_model = self.env.context.get('active_model')
    active_ids = self.env.context.get('active_ids') or []
    if active_model == 'iscapop.category_model' and active_ids:
        vals['category_id'] = active_ids[0]
    return vals

    Contexto típico al abrir desde otra vista:
    - active_model: modelo de origen.
    - active_id/active_ids: registro(s) seleccionados.
    - default_...: prefija valores en el wizard.

    6) Patrón de varios pasos

    • Añade un campo state (step1, confirm, done, …).
    • Cambia el layout con attrs="{'invisible': ...}" según el estado.
    • Devuelve la acción sobre sí mismo para refrescar la vista (ver _reopen_self).

    7) Seguridad y acceso

    • Define ACLs si el wizard se abre desde menús públicos del módulo.
    • Si solo se invoca desde botones restringidos, puede bastar con permisos del modelo de negocio afectado.
    • En operaciones de creación en lote, considera sudo() cuidadosamente (audita que el usuario tenga permiso y que no expongas elevación indebida).

    8) Errores y validaciones

    • Usa @api.constrains para validar campos del wizard.
    • Lanza UserError/ValidationError con mensajes claros.
    • Los errores detienen la acción y mantienen abierto el modal, mostrando la incidencia.

    9) Cierre del wizard

    • Para cerrar la ventana modal, retorna {'type': 'ir.actions.act_window_close'}.
    • También puedes redirigir a otra acción (por ejemplo, abrir los registros creados): 
      return {
    'type': 'ir.actions.act_window',
    'name': 'New Items',
    'res_model': 'iscapop.item_model',
    'view_mode': 'tree,form',
    'domain': [('category', '=', self.category_id.id)],
}

    10) Buenas prácticas

    • Mantén el wizard simple y específico (una acción clara).
    • Evita lógica pesada en @api.onchange; valida en servidor.
    • No persistas datos de negocio en el wizard; crea o actualiza modelos reales.
    • Documenta qué contexto espera tu wizard y qué permisos requiere.

    11) Ejemplo mínimo (one-shot)

    from odoo import models, fields

class SimpleExportWizard(models.TransientModel):
    _name = 'demo.simple_export_wizard'
    _description = 'Simple Export Wizard'

    export_format = fields.Selection([('csv','CSV'),('xlsx','Excel')], default='csv')

    def action_export(self):
        # Realiza la exportación y devuelve una acción para descargar/abrir
        return {'type': 'ir.actions.act_window_close'}

    Y su acción para abrirlo como modal: 

    <record id="action_simple_export_wizard" model="ir.actions.act_window">
  <field name="name">Simple Export</field>
  <field name="res_model">demo.simple_export_wizard</field>
  <field name="view_mode">form</field>
  <field name="target">new</field>
</record>

    12) Checklist rápido

    • [ ] Modelo TransientModel con los campos necesarios.
    • [ ] Vista form con footer (botones type="object" y special="cancel").
    • [ ] Acción ir.actions.act_window con target="new".
    • [ ] Uso correcto de contexto (active_model, active_ids, default_*).
    • [ ] Validaciones (@api.constrains) y mensajes claros.
    • [ ] Cierre/Redirección al terminar.

    Conclusión

    TransientModel es la herramienta idónea para interacciones temporales y acciones guiadas en Odoo. Dominar contexto, vistas modales, estados y retorno de acciones te permitirá construir wizards limpios, seguros y reutilizables.
