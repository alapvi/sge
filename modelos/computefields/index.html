    Campos calculados (Computed Fields)

    En esta sección veremos los campos calculados del ORM de Odoo y cómo aplicarlos en el módulo task_app.

    [Referencia oficial (Odoo, Computed fields)])https://www.odoo.com/documentation/18.0/developer/reference/backend/orm.html?highlight=fields%20char#computed-fields)

    1) ¿Qué es un campo calculado?

    Un campo calculado no se escribe directamente por el usuario, sino que su valor se calcula mediante un método Python (compute). Puede ser no persistente (se calcula “al vuelo”) o persistente si se define con store=True (el valor se guarda en la BD y se recalcula cuando cambian sus dependencias).

    Claves: - compute="_metodo_": apunta al método que asigna el valor al campo. - @api.depends(...): declara las dependencias que detonan el recálculo. - store=True: guarda el resultado y lo recalcula al cambiar dependencias (mejor rendimiento de lectura y permite usar en dominios/búsquedas). - readonly=True: típico en campos calculados (salvo que uses un inverse). - inverse="_metodo_": opcional; permite escribir el campo y propagar cambios a otros campos. - compute_sudo=True: ejecuta el cómputo con privilegios de superusuario (útil si el usuario no puede leer todos los datos requeridos para el cálculo).

    2) Ejemplo práctico — Fecha de última modificación lógica de la tarea

    Añadimos a task_app.task_model un campo calculado modification_date que se actualiza cuando cambian ciertos campos funcionales de la tarea: name, description, responsible_id, category_id, is_done.

    Nota: en Odoo las relaciones a registros suelen llevar sufijo _id (por ejemplo, responsible_id).

    # task_app/models/task_model.py
from odoo import api, fields, models

class TaskModel(models.Model):
    _name = "task_app.task_model"
    _description = "Task (basic model)"

    name = fields.Char(string="Name", required=True, index=True)
    description = fields.Text(string="Description")
    is_done = fields.Boolean(string="Done", default=False)
    responsible_id = fields.Many2one("res.users", string="Responsible")
    category_id = fields.Many2one("task_app.category_model", string="Category", ondelete="set null", index=True)

    # Campo calculado (almacenado) con la última "modificación lógica"
    modification_date = fields.Datetime(
        string="Last Change",
        compute="_compute_last_change",
        store=True,
        readonly=True,
        help="Fecha/hora del último cambio relevante en la tarea."
    )

    @api.depends("name", "description", "responsible_id", "category_id", "is_done")
    def _compute_last_change(self):
        # Usar fields.Datetime.now() asegura zona horaria gestionada por Odoo
        now = fields.Datetime.now()
        for rec in self:
            rec.modification_date = now

    Cómo funciona: - Cada vez que Odoo detecta una escritura en cualquiera de las dependencias listadas, vuelve a ejecutar _compute_last_change, estableciendo la fecha actual. - Con store=True, el valor queda persistido y es utilizable en dominios, ordenaciones y búsquedas.

    Buenas prácticas: - Evita dependencias autorreferenciadas que creen bucles (no agregues modification_date a @api.depends). - Si el cálculo necesita leer datos que algunos usuarios no pueden ver, considera compute_sudo=True. - Si quieres que este valor refleje cualquier cambio (técnico) en la fila, puedes apoyarte también en la columna write_date estándar de Odoo; el ejemplo de arriba define una “última modificación lógica” según tus campos clave.

    3) Campos calculados: parámetros y patrones comunes

    3.1) store=True vs sin store

    • Sin store: se calcula al acceder; no puede usarse en dominios SQL ni ordenaciones en servidor; puede impactar rendimiento al leer muchas filas.
    • Con store=True: se recalcula al cambiar dependencias y se persiste; sí puede usarse en dominios/ordenaciones y suele ser mejor para listas/grids grandes.

    3.2) inverse (cuando quieres editar el campo)

    Si quieres permitir que el usuario edite un campo calculado y propagar ese cambio a los campos base:

    total = fields.Monetary(compute="_compute_total", inverse="_inverse_total", store=True)

def _compute_total(self):
    for r in self:
        r.total = (r.price_unit or 0.0) * (r.qty or 0.0)

def _inverse_total(self):
    # Ejemplo simplificado: ajustar qty manteniendo price_unit
    for r in self:
        if r.price_unit:
            r.qty = (r.total or 0.0) / r.price_unit

    3.3) compute_sudo=True

    • Útil cuando el cálculo requiere leer registros restringidos por ACLs/reglas.
    • Ejemplo: count_all_tasks = fields.Integer(compute="_compute_counts", compute_sudo=True, store=True)

    3.4) @api.depends_context y @api.depends_domain (avanzado)

    • Permiten recalcular cuando cambia el contexto (ej. moneda) o el dominio usado en campos relacionales. Útiles en escenarios multicompañía, multi-moneda, etc.

    4) Diferencias con related y onchange

    • related: copia/expone el valor de otro campo (misma semántica que el original). Puede ser store=True para persistir. No ejecutas un método de cómputo libre, solo “mapeas” un campo existente.
    • onchange: lógica de interfaz (cliente) para prefijar/calcular valores cuando se cambian otros campos en la vista. No garantiza coherencia en procesos de servidor (importaciones, RPC, automatizaciones). Para lógica de negocio persistente → usa compute.

    5) Validación y rendimiento

    • Mantén el cómputo determinista: que dependa únicamente de las dependencias listadas (salvo casos puntuales como el ejemplo de “ahora”).
    • Si el cálculo es costoso, intenta vectorizar (leer datos de todos los registros primero) para minimizar queries por registro.
    • Revisa índices en los campos base que uses para búsquedas y ordenaciones si el campo calculado es store=True y se consulta mucho.

            <field name="description"/>
            <field name="responsible_id"/>
            <field name="category_id"/>
            <field name="is_done"/>
            <field name="modification_date" readonly="1"/>
          </group>
        </sheet>
      </form>
    </field>
  </record>
</odoo>

    7) Resumen

    • Declara el campo con compute= y lista dependencias con @api.depends.
    • Usa store=True si necesitas búsquedas/ordenaciones o mejorar rendimiento.
    • Añade inverse si el usuario debe poder escribir en un campo calculado.
    • Considera compute_sudo=True cuando el cálculo lea datos restringidos.
    • Para “última modificación”, tu ejemplo con fields.Datetime.now() y dependencias seleccionadas es correcto para medir la modificación lógica de la tarea.
