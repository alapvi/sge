    Visual Studio Code en remoto

    La forma recomendada de trabajar con Odoo en un servidor Debian o Ubuntu es instalar Visual Studio Code en el equipo local y conectarse al servidor mediante SSH. El código, las extensiones de desarrollo, la terminal y los comandos se ejecutan en el servidor remoto, mientras que la interfaz de VS Code permanece en el equipo local.

    Este procedimiento utiliza la extensión Remote - SSH. No es necesario instalar VS Code completo en el servidor ni instalar manualmente VS Code Server: la extensión lo descarga y lo actualiza automáticamente al realizar la primera conexión.

    Requisitos

    Equipo local

    • Visual Studio Code para macOS, Linux o Windows.
    • Un cliente compatible con OpenSSH. En Linux y macOS normalmente ya está instalado; en Windows se puede utilizar el cliente OpenSSH incluido en el sistema.
    • La extensión Remote - SSH. También puedes instalar el paquete Remote Development.

    Servidor remoto Debian/Ubuntu

    El servidor debe ser accesible por SSH y tener, como mínimo, 1 GB de RAM. Se recomiendan 2 GB de RAM y 2 núcleos de CPU. Para las versiones actuales de VS Code Server se recomienda una distribución de 64 bits basada en glibc con glibc 2.28 o posterior, como Debian 10+ o Ubuntu 20.04+.

    Instala y activa el servidor SSH junto con las utilidades que Remote-SSH necesita:

    sudo apt update
sudo apt install openssh-server bash tar curl ca-certificates -y
sudo systemctl enable --now ssh

    Comprueba desde el propio servidor que SSH está activo:

    sudo systemctl status ssh --no-pager
ss -tln | grep ':22'

    Si utilizas ufw, permite SSH antes de cerrar la sesión actual:

    sudo ufw allow OpenSSH
sudo ufw status

    El usuario que utilizarás para conectarte debe tener permisos sobre el código de Odoo y no necesita ser root.

    Configurar el acceso SSH

    Desde el equipo local, comprueba primero que puedes entrar al servidor:

    ssh usuario@servidor

    Para evitar introducir la contraseña en cada conexión, se recomienda utilizar una clave Ed25519. Ejecuta estos comandos en el equipo local, no en el servidor:

    ssh-keygen -t ed25519 -C "vscode-remoto"
ssh-copy-id usuario@servidor
ssh usuario@servidor

    Protege la clave privada y no la copies al servidor. Si ssh-copy-id no está disponible, añade manualmente el contenido de ~/.ssh/id_ed25519.pub del equipo local a ~/.ssh/authorized_keys del usuario remoto.

    Archivo de configuración SSH

    Para no repetir los parámetros de conexión, crea o edita ~/.ssh/config en el equipo local:

    Host sge-odoo
    HostName servidor.example.com
    User usuario
    Port 22
    IdentityFile ~/.ssh/id_ed25519

    Prueba el alias antes de abrir VS Code:

    ssh sge-odoo

    Si el servidor solo es accesible mediante un salto intermedio, puedes añadir ProxyJump bastion al bloque Host y probar de nuevo la conexión desde una terminal.

    Conectarse desde VS Code

    1. Instala y abre VS Code en el equipo local.
    2. Instala la extensión Remote - SSH.
    3. Abre la paleta de comandos con Ctrl+Shift+P o Cmd+Shift+P.
    4. Ejecuta Remote-SSH: Connect to Host....
    5. Selecciona sge-odoo o introduce usuario@servidor.
    6. Selecciona Linux si VS Code pregunta por la plataforma remota.
    7. Acepta la huella SSH la primera vez que conectes.
    8. Abre la carpeta remota donde está el proyecto, por ejemplo: /opt/sge-source.

    VS Code instalará automáticamente VS Code Server en el directorio del usuario remoto. La conexión aparecerá en la esquina inferior izquierda y las terminales nuevas se ejecutarán en el servidor, no en el equipo local.

    Extensiones y herramientas remotas

    Cuando la ventana está conectada por SSH, instala en el servidor las extensiones que necesiten analizar o ejecutar el código remoto, por ejemplo:

    • Python y Pylance para el desarrollo Python.
    • YAML para archivos de configuración y Compose.
    • GitLens u otras extensiones de Git, si las necesitas.

    Las extensiones de interfaz, como temas e iconos, permanecen en el equipo local. VS Code muestra las extensiones remotas agrupadas bajo el nombre del servidor.

    La terminal integrada, Git, Python, Docker y los comandos de Odoo se ejecutan en el host remoto. Si Docker está instalado en ese host, la extensión de Docker también debe instalarse en la ventana remota para administrar sus contenedores.

    Acceder a Odoo desde el equipo local

    Para probar Odoo sin publicar el puerto 8069 en Internet, utiliza el reenvío de puertos de Remote-SSH:

    1. Inicia Odoo en el servidor escuchando en el puerto 8069.
    2. Abre la vista Ports de VS Code.
    3. Añade o detecta el puerto remoto 8069.
    4. Abre la dirección local que VS Code muestra para ese puerto.

    También puedes definir un reenvío permanente en ~/.ssh/config del equipo local:

    Host sge-odoo
    HostName servidor.example.com
    User usuario
    IdentityFile ~/.ssh/id_ed25519
    LocalForward 127.0.0.1:8069 127.0.0.1:8069

    Con esta configuración, Odoo queda disponible en http://127.0.0.1:8069 en el equipo local mientras la conexión SSH esté activa.

    Conectividad y solución de problemas

    El servidor remoto necesita poder instalar VS Code Server. Asegúrate de que el servidor o el equipo local tengan salida HTTPS por el puerto 443 hacia:

    • update.code.visualstudio.com
    • vscode.download.prss.microsoft.com
    • marketplace.visualstudio.com y *.gallerycdn.vsassets.io para instalar extensiones.

    Si la descarga desde el servidor está bloqueada, configura en los ajustes locales Remote.SSH: Local Server Download como always para descargar VS Code Server en el equipo local y transferirlo por SSH.

    Para diagnosticar una conexión fallida:

    ssh -v sge-odoo

    En VS Code, revisa el canal Output > Remote - SSH. Los problemas más habituales son una clave SSH con permisos incorrectos, un puerto bloqueado, un usuario sin directorio escribible o una distribución remota sin bash, tar o curl.
